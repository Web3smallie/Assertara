Authoritative interface, schema, timeout, retry, limit, and error reference
for `src/agent/`. This document describes what the code does today; code and
tests are the source of truth — update all three together.

## 2. Model client interfaces

Two interfaces; runners declare which they need and throw loudly without it:

- `complete({ system, input, schema, schemaName, effort, previousResponseId, maxOutputTokens, timeoutMs })` → `{ content, usage, estimatedCostUsd, responseId }`. `content` is parsed JSON; malformed JSON is a typed non-retryable `invalid_response` error.
- `nextTurn({ system, effort, responseId, graph, ledger })` → `{ actions: [{ tool, args }], usage?, estimatedCostUsd?, responseId?, notes?, stop?, stopReason? }`.

Real implementation: `SparkAdapter`. Tests use scripted stubs.

## 3. Spark API surface used

- `POST {base}/responses` with `{ model, input, reasoning: { effort }, text: { format: { type: 'json_schema', name, schema, strict: true } }, tools?, previous_response_id?, max_output_tokens?, prompt_cache_key? }`.
- `POST {base}/responses/input_tokens` preflight (exact count + validation, no generation).
- Defaults: model `muse-spark-1.3`, `prompt_cache_key: 'assertara-investigate'`, timeout 120000ms.
- Normalized result: `{ id, status, text, toolCalls: [{ callId, name, argsRaw }], reasoningItems, usage, estimatedCostUsd, cachedTokens }`.
- Cost uses documented standard-tier rates ($1.25/$0.15/$4.25 per MTok) applied ONLY when `usage` is present; otherwise `null` — never invented.

## 4. Tool contract

- Call shape: `runTool(name, args)` → result object, or throws `Error`.
- Validation (two layers, same rules): the orchestrator runs presence + per-tool `validate()` format checks pre-execution and records failures as invalid actions (never executed, never counted as execution failures, never retried); `runTool` re-validates defensively and throws before any execution for direct callers.
- `UNAVAILABLE` tools return `{ status: 'UNAVAILABLE', tool, requirements }` instead of running.
- Orchestrator additionally: unknown/unavailable/invalid actions recorded as failed actions (never executed); duplicates by `(tool, sha256(args))` suppressed and counted in `ledger.deduped`.

## 5. Evidence requirements

- Node: `{ id (E-###, app-minted), kind, producer: USER|TOOL|MODEL, tool_ref?, input_hashes[], payload, created_turn }`.
- Edges: `SUPPORTS | CONTRADICTS | REFINES | SUPERSEDES | DERIVED_FROM`, both endpoints must exist.
- Findings cite `supporting[]`/`contradicting[]` IDs; `validateRefs` must pass before adjudication.
- Experimental evidence is marked `kind: 'Experimental'` or `payload.experimental === true` and can never support `VERIFIED` (verifier gate).

## 6. Timeouts

| Layer | Default | Notes |
|---|---|---|
| Adapter request/preflight | 120000ms | Per-attempt; overridable per call |
| Orchestrator tool execution | 30000ms (`budget.toolTimeoutMs`) | Timed-out tools recorded as failures, loop continues |
| Simulator `forge` spawn | 8000ms | Existing service behavior; timeout → `FAILED` |
| Extension backend POST | 120000ms | Existing extension behavior |

## 7. Retry rules

- Retry **once** (max 2 attempts): HTTP 429, HTTP 5xx, timeouts.
- Backoff: honor server `Retry-After`, capped at 10s; otherwise 500ms fixed.
- **Never retried:** 4xx (incl. 400 validation, 401 auth), malformed JSON responses, tool validation failures, unknown tools, deterministic tool errors, model-client `complete()` JSON errors.
- Orchestrator performs no retries of its own: one attempt per validated action; failures become `ToolFailure` evidence and the loop continues or terminates honestly.

## 8. Resource limits

- Orchestrator budget defaults: `maxTurns 8`, `maxToolCalls 24`, `maxUsd 2.00`, `maxIdleTurns 2`. Exhaustion → `INCOMPLETE` with `stopReason`; never a forced verdict.
- Input caps: client visible text 8000 chars (controller), repo-review file 200KB / 60KB prompt slice (features), screenshot payloads bounded by Express 25mb JSON limit.
- Chain reads: `maxLogs` default 500; block window must be specified or defaults to tip−20000.

## 9. Error behavior

- `SparkApiError { status, type, code, message, retryable, retryAfterMs }`. Types: `rate_limit_error`, `server_error`, `invalid_request_error`, `authentication_error` (from server), `invalid_response`, `timeout`, `configuration_error` (missing/placeholder key — fails before any network call).
- Tool errors: thrown `Error` with `toolName: reason` messages; orchestrator catches per-action.
- Feature runners: return `{ status: 'OK'|'PARTIAL'|'FAILED'|'GATED'|'EXPERIMENTAL'|'UNAVAILABLE'|'REJECTED', ... }`; programmer errors (missing model/inputs) throw.
- Verifier statuses: `VERIFIED | LIKELY | HYPOTHESIS | REJECTED | INCONCLUSIVE | INCOMPLETE` (meanings in `verifier.js` `STATUSES`). Eight gates (all must pass): has-support (non-empty `supporting[]`), ids-resolve, no-unresolved-contradictions (Finding-node edges), execution-truth (genuine: EXECUTED/passed/VULNERABILITY_REPRODUCED/PATCH_VERIFIED), model-cannot-verify, no-experimental-support, no-failed-support (failed/unavailable/mock ToolResults reject), contradictions-resolved (`contradicting[]` needs a superseding record or REFINES/SUPERSEDES edge). Experimental-support and contradiction failures alone cap at HYPOTHESIS; every other failure rejects.
- Simulation statuses: `EXECUTED | FALLBACK | FAILED | NOT_RUN` — only `EXECUTED` may claim EVM execution.
- Secrets: API keys travel only in the `Authorization` header; never in bodies, errors, logs, or reports.

## 10. Scheduler contract (`scheduler.js`)

- State: `<dir>/nightwatch.json` (`{ version: 1, targets: {id: {...}}, alerts: [] }`), written atomically via temp-file + rename. Lock: `<dir>/.nightwatch.lock` (`{token, pid, at}`), exclusive-create with stale recovery after `stalenessMs` (default 120s). Target ids are internal (`w_*`); no user input becomes a path.
- Target: `{ id, address (0x), label ≤120 chars, intervalMs (5s–7d, default 1h), paused, baseline|null, lastCheck, nextDue, consecutiveFailures, lastAlertHash, lastError≤500 chars }`. No secrets are ever stored.
- Semantics: sequential checks (concurrency 1); missed runs fire exactly once with `nextDue` reset to now + interval; failures back off as `min(interval * 2^failures, maxBackoffMs)` without stopping other targets; alerts fire only on new change-hashes (baseline advances on alert; history capped, oldest pruned).
- Lifecycle: `start()` acquires the lock (throws if a fresh holder exists) and runs one catch-up tick, then ticks every `tickMs`; `stop()` clears the timer and releases only its own lock token. `tickOnce()` is the deterministic entry point (works standalone; acquires/releases when not started). The loop runs only while the process is alive — never presented as 24/7 monitoring.
- Corrupt state: unparseable/schema-mismatched files are quarantined to `nightwatch.corrupt-<ts>.json` and replaced with a fresh store (reported, never silent); malformed target entries are dropped with a count; one bad target never crashes a tick.

## 12. PDF ingestion contract (`pdfIngest.js`, `pdf_extract` tool)

- Interface: `ingestAuditPdf({ data: Buffer|Uint8Array|base64, filename?, pageImages?, limits? }, { ocr? })` → `{ status:'OK', feature:'F10_audit', lane:'ingest', doc:{sha256,bytes,filename,pages,textChars}, pages, findings, warnings }`. `toLedgerIntake(result)` → `runAuditIntake` input. No model calls in this lane: segmentation is deterministic regex, so embedded instructions are inert data by construction.
- Validation order: base64/input shape → `%PDF-` magic (first 1KB) → byte cap (default 5MiB) → proxy preflight page-count cap (default 50) → extraction → char cap (default 200k) → findings cap (default 100). Over-limit docs are REJECTED with typed `PDF_*` codes, never silently truncated.
- Provenance: every page is `PDF_TEXT` | `OCR_TEXT` (caller-supplied image + existing OCR service) | `NO_TEXT` + explicit warnings (`PAGE_N_NO_TEXT`, `PAGE_N_OCR_EMPTY/FAILED`). Findings carry verbatim quotes (truncation marked `…[truncated N chars]`), `startPage/endPage`, severity only when the heading states it.
- Code refs (`FILE|FUNCTION|ADDRESS`) are `MENTIONED_IN_REPORT` observations — the report names them. Never verified code, never proof of exploitability. Ledger intake ids are deterministic (`<sha8>-Fnn`); all records enter `UNRESOLVED` and move only via `runAuditTransition`. Status vocabulary note: the ledger's fixed state is `VERIFIED_FIXED` (requires `{passed:true, logs}`); there is no bare `FIXED` status — a fix claim is `FIX_CLAIMED` until proven.

## 13. Harness contract (`harness.js`, `sandbox_exec` tool, F15 execute lane)

- Interface: `submitHarnessRun({ kind: static|execute|reproduce|verify-patch, files, entry?, criterion?, poc?, suite?, timeoutMs?, maxLogChars? }, { executor?, workspaceRoot?, capabilities? })`. Validation throws coded `HarnessError`s before any staging. `static` returns `STATIC_ANALYSIS_ONLY` (no detection, no workspace). Without an executor, execute-kind requests return `EXECUTION_UNAVAILABLE` with live detection evidence + requirements; nothing runs on the host, ever.
- Run statuses: `EXECUTION_FAILED` (errored before criterion evaluation), `EXECUTION_TIMED_OUT` (wall clock exceeded; abort requested; never a finding), `EXECUTION_COMPLETED` (finished, no criterion satisfied — completion ≠ reproduction), `VULNERABILITY_REPRODUCED` (finished + explicit criterion met), `NOT_REPRODUCED` (finished + criterion evaluated + not met; not proof of safety), `PATCH_VERIFIED` (verify-patch: PoC no longer reproduces AND regression suite passes; supplies `{passed:true, logs}` testEvidence for the ledger).
- Vocabulary mapping (no conflicts): harness `EXECUTION_*` describes the run; simulator `EXECUTED/FALLBACK/FAILED/NOT_RUN` describes EVM simulation attempts; F15 static drafts stay `UNEXECUTED`; the audit ledger alone sets `VERIFIED_FIXED` (via `runAuditTransition`, consuming harness `testEvidence`). Static findings, hypotheses, timeouts, and unavailable execution can never produce `PATCH_VERIFIED` or feed `VERIFIED_FIXED`.
- Evidence per run: `runId`, `requestHash`/`filesHash` (sha256), argv `command`, `exitCode`/`signal`, bounded logs with explicit truncation markers, `criterion` + `criterionMet`, environment metadata (executor name, required constraints). Per-run workspace under `data/.harness-runs/` (configurable), removed in `finally` after success, failure, and timeout. Command policy: argv exec only (never a shell), tool allowlist `forge|node|python3`, arg count/length/NUL checks.
- Detection: `detectCapabilities()` probes `docker` (binary + daemon) and `podman` (binary + daemon) with 5s timeouts; reports `{available, version?, error?}` + `canExecuteIsolated`. WSL is deliberately excluded: it provides no containment and is not an acceptable substitute. Verified 2026-10-27 on this machine: Docker absent, Podman absent, WSL feature not installed → `canExecuteIsolated: false`.
- Docker/Podman adapter contract (SHIPPED Phase 18 as `src/agent/sandbox.js`; authoritative spec now §27): verify runtime+daemon+image identity BEFORE any run; run `docker|podman run --rm --pull never --network none --cap-drop ALL --security-opt no-new-privileges --read-only --tmpfs /tmp:rw,noexec,nosuid,size=64m --memory 512m --cpus 1.0 --pids-limit 128 --stop-timeout 5 --name <per-run> -v <workspace>:/work --workdir /work --entrypoint <tool> <pinned-image> <args...>` with runner-side timeout kill (`kill` + `rm -f`); mount ONLY the per-run workspace (never the project root, home, `.env`, Git/SSH credentials, or the runtime socket); pass no secrets via env/args; return `{exitCode, signal?, stdout, stderr}`. ## 14. Audio ingestion contract (`audioIngest.js`, `transcribe_audio` tool, F8 audio lane)

- Interface: `ingestAudio({ data: Buffer|Uint8Array|base64, filename?, mimeType?, timeoutMs?, maxBytes?, maxDurationSec?, maxSegments?, maxChars? }, { backend?, capabilities? })`. Validation order: base64/input shape → byte cap (default 10MiB) → magic-byte format sniff (filename never trusted) → WAV/PCM parse with duration math → duration cap (default 600s) → backend stage. Over-limit/malformed/unsupported inputs throw typed `AUDIO_*`/`UNSUPPORTED_FORMAT`/`MALFORMED_AUDIO` codes, never silent skips.
- Formats: only `wav-pcm` is parseable (hand-written RIFF parser: format tag must be 1, channels 1–8, rate 4k–192kHz, depth 8/16/24/32, data chunk must fit the file). MP3/MP4/OGG/unknown are rejected as `UNSUPPORTED_FORMAT` with the detected format named: decoding them requires ffmpeg, which is absent.
- Transcription statuses: `TRANSCRIPTION_COMPLETED` (all segments timestamped), `TRANSCRIPTION_PARTIAL` (backend `partial:true`, missing ranges, or untimestamped segments — each marked), `TRANSCRIPTION_UNAVAILABLE` (no backend; carries live detection + requirements). Backend throws → `BACKEND_ERROR`; wall-clock exceeded → `TRANSCRIPTION_TIMEOUT` with abort requested. Segment caps enforced by rejection, never silent truncation.
- Provenance: segments carry `TRANSCRIBED` + backend/model/language identity, timestamps as supplied (null + warning when missing), confidence only when 0..1 (else null + warning), speaker ONLY when the backend declares `diarized:true` (else dropped + warning). `ingestTranscript()` normalizes caller text with `TRANSCRIPT_PROVIDED` provenance — never backend identity, never confidence, never labeled transcription. F8 annotations are enriched with verbatim `quote` + `start`/`end`; turn text is untrusted data (prompt-hardened); speaker identity/emotion/intent inference stays forbidden.
- Detection: `detectAudioCapabilities()` probes `ffmpeg`/`ffprobe` binaries and reports `sttBackend:{available:false}` + `canTranscribe:false`. Verified 2026-10-27 on this machine: ffmpeg absent, ffprobe absent, no STT backend → transcription unavailable; transcript-only lane unaffected.

Decoding non-WAV formats additionally requires ffmpeg with a version probe test.

## 15. Historical discovery contract (`chain.js` discovery, F6 sentinel, `chain_history` tool)

- Interface: `discoverApprovals({ owner, tokens?, chainId=1, client?, rpcUrl?, fromBlock?, toBlock='latest', chunkBlocks=500, maxLogs=500, maxCalls=100, perChunkCap=2000, sleep? })`. Validation order: owner/token/chain shape → chunk/limit shape → provider chain check (when the client exposes `getChainId`; mismatch throws `CHAIN_MISMATCH`) → tip resolution → range validation. All RPC calls go through `withRetryOnce` (contracts §7: one retry on 429/5xx/timeout/network, Retry-After capped 10s else 500ms; restrictions/4xx/unknown fail closed with no retry).
- Query shape: address-scoped `getLogs({ address, event: APPROVAL_EVENT, args: { owner } })` per token × chunk. viem has NO raw `topics` parameter (unknown props are silently dropped — verified live); filters MUST use `event`+`args`. Returned logs are re-verified client-side (topics[0], topics[1], address); foreign logs are counted as `foreignLogsFiltered`, never ingested. Events dedup by `txHash:logIndex` across chunks; latest event per (token, spender) wins; live `allowance()` enriches each pair (failure → `null`, honestly).
- Coverage: aggregate ∈ `COMPLETE_WITHIN_REQUESTED_SCOPE` (zero gaps) / `PARTIAL_COVERAGE` (some chunks failed or capped) / `HISTORY_UNAVAILABLE` (zero chunks succeeded). Per-gap failure taxonomy ∈ `QUERY_REJECTED` (permanent: restrictions, 4xx, invalid params) / `QUERY_FAILED` (transient exhausted). Coverage records requested scope, retrieved scope (chunks, calls, events, foreign-filtered), gaps with ranges+reasons, provider `{endpoint(host-only, never credentials), chainId, tip}`, limitations, and bounded errors. Legacy `truncated` bool preserved: true only under `max-logs-cap`.

## 16. Dossier contract (`dossier.js`, F7 runner)

- Interface: `buildDossier({ address, chainId=1, client?, rpcUrl?, sourceProvider?, abi?, history?: {tokens?, fromBlock?, toBlock?, maxLogs?}|false })`. Nine sections: identity, bytecode, source, abi, privileges, proxy, history, limitations, riskObservations. Every section/item carries a standing ∈ `OBSERVED` (retrieved data) / `INFERRED` (derived from documented evidence) / `UNAVAILABLE` (could not retrieve) / `UNRESOLVED` (insufficient evidence). Vocabulary mapping: `UNRESOLVED` matches the ledger's insufficient-evidence meaning; the other three are evidence-grade labels below the verifier's `VERIFIED/LIKELY/HYPOTHESIS` adjudications — a dossier can never output a finding status, structurally.
- Bytecode: `eth_getCode` presence/length + keccak256 `codeHash`; EOA absence is `OBSERVED` (observed absence, not missing data). Proxy: EIP-1967 implementation/admin/beacon slots + EIP-1167 minimal-proxy bytecode pattern (implementation extracted); assessment ∈ `proxy-indicated` / `no-proxy-indicators` (indicator language only — bespoke pre-1967 layouts are a documented unresolved limitation, verified live against USDC).
- Source: ONLY via injected `sourceProvider.fetch({address, chainId}) → {ContractName?, CompilerVersion?, LicenseType?, SourceCode (string or Etherscan multi-file JSON), ABI?}`; none configured → `UNAVAILABLE` + requirements. Provider faults (fetch throw, empty/malformed payload) degrade the section, never the dossier. Multi-file sources normalize to `[{path, content}]` with a sha256 `sourceHash`.
- ABI: caller-supplied wins (origin `PROVIDED`, malformed → loud `MALFORMED_ABI` throw) over provider ABI (origin `verified-source`); neither → `UNAVAILABLE`/`UNRESOLVED`. Functions parsed with computed selectors (`keccak256(signature)[0:4]`), mutability, payability.
- Privileges: deterministic pattern scans — source basis (modifier/function regex with `file:line` refs) preferred over ABI basis (name-only heuristics, explicitly weak). Observations are investigation leads with capped evidence refs, never verdicts. History: owner-side `discoverApprovals` + exposure + coverage passthrough (failures contained as `UNAVAILABLE`); risk observations link txHash/logIndex evidence with severity ∈ `info`/`notable` only.
- `runDossier` returns `{ status, feature, meta (superset incl. beacon), dossier, synthesis }`; synthesis is model interpretation over the dossier with `verified:false`, hardened prompt (cite dossier evidence, never call malicious/safe, never claim verification).
- Source-provider adapter contract (NOT shipped — no explorer key configured): MUST implement `fetch`, MUST record provider name + `fetchedAt`, MUST NOT invent metadata (empty SourceCode → no-source, not unverified-guess), and MUST ship with a live test against the real explorer proving retrieval + a negative test for unverified contracts. Etherscan-compatible APIs currently require registration/API keys — a paid/credential dependency that needs explicit approval before adoption.
- Verified live 2026-10-27 (publicnode, explicit rpcUrl): USDC dossier — bytecode OBSERVED (2186 bytes + codeHash), EIP-1967 slots empty (correct: pre-1967 layout) with self-documenting limitation, source/ABI/privileges honestly unavailable, history OBSERVED/PARTIAL as expected on the free tier.

## 17. Finding Q&A contract (`askAbout.js`, F9 finding path)

- Interface: `answerFindingQuestion({ findingId?, finding?, findings?, evidence: {nodes}|Array, question }, { model? })`. Exactly one of `findingId` (resolved from `findings[]`, else `FINDING_NOT_FOUND`) or `finding` (`{id, claim|description, status?, supporting?[], contradicting?[]}`); both → `FINDING_AMBIGUOUS`. Evidence items normalize from graph nodes (`{id, kind, producer, payload}`) or explicit `{ref, kind, summary}` (supports txHash:logIndex/file:line refs). Question capped at 2000 chars, 50 evidence items, 15k context chars — all with explicit truncation markers.
- Deterministic grounding (outside model control): supporting/contradicting refs resolved against the registry (unknown → `missingRefs`, never faked); `statusNote` computed from finding status (FIX_CLAIMED is explicitly never-fixed language; only VERIFIED_FIXED permits verification vocabulary); experimental linked evidence sets `experimentalSupport` + `experimentalCaveat`. The model receives ONLY the finding summary + resolved evidence + question (minimal context, hardened prompt: evidence/question untrusted, cite-only-citable, never invent or verify).
- Output validation: `ASK_SCHEMA` (`answer`, `citations[]`, `answerable` full|partial|none, `uncertaintyNote`, `missingEvidence`) with Meta strict-schema shape (`additionalProperties:false`, all props required — discovered live). Citations outside the citable set are dropped + `PARTIAL`. Model prose is scanned for verification phrases; any hit without VERIFIED_FIXED status sets `unverifiedClaimDetected` + `PARTIAL` + authoritative correction (status note wins). Answering never mutates the finding or its status.
- Failure behavior: missing model, model throw, or malformed output → `DEGRADED` with a deterministic digest (claim, status, statusNote, resolved refs, missing refs — zero interpretation). Legacy `runAskAbout({graphExport, question})` path preserved unchanged for frozen-graph Q&A.

## 18. Audit assessment contract (`auditAssess.js`, F10 assess lane)

- Interface: `assessAuditFindings({ records, report, sources?, remediations? }, { model? })` — max 20 findings, 30 source files (200KB each). `records` are `runAuditIntake` ledger records; `report` is `ingestAuditPdf` output; the two align BY INDEX (length mismatch throws `ASSESS_MISMATCH`). ## 27. Sandbox executor contract (`sandbox.js`, F15 execute lane, Phase 18)
- Enablement is OPERATOR configuration only: `submitHarnessRun(input, { sandbox: { enabled, runtime?, image, expectedDigest?, limits?, spawnFn? }, workspaceRoot? })`. The `sandbox_exec` tool never passes `sandbox`, so model calls cannot enable execution (sandbox T15). - Verification (`verifySandbox`, no untrusted execution): normalize runtime (`docker|podman|auto`) → validate image ref (registry grammar, ≤300 chars) → validate `expectedDigest` (`sha256:<64hex>`) and absolute `workspaceRoot` → probe each candidate runtime (`--version`, then `info`) → `image inspect` for Id + RepoDigests → digest match (image Id or RepoDigest suffix). Missing infrastructure NEVER throws; invalid operator config throws `SANDBOX_CONFIG`, which the harness maps to `EXECUTION_UNAVAILABLE` (stage `config`), never to a run (sandbox T1–T4, T6).
- Run argv (Docker/Podman-compatible; `buildRunArgv` self-checks every mandatory flag and throws `SANDBOX_INTERNAL` if one is missing): `--rm --pull never --network none --cap-drop ALL --security-opt no-new-privileges --read-only --tmpfs /tmp:rw,noexec,nosuid,size=64m --memory 512m --cpus 1.0 --pids-limit 128 --stop-timeout 5 --name assertara-<wsbase>-<pid>-<seq> -v <workspace>:/work --workdir /work --entrypoint <tool> <image> <args...>`. The entry is the harness-validated `{tool, args}` re-validated here (shape + NUL checks); its first token becomes `--entrypoint` (overriding any image ENTRYPOINT such as `/bin/sh -c`, which would otherwise swallow arguments) and the remaining args trail the image, unmodified; no shell exists on this path (T17). `workspaceDir` must be absolute, NUL-free, strictly inside `workspaceRoot`, with a safe basename — escapes are rejected before any runtime call (T7–T8).
- Deviations from the pre-Phase-18 §13 sketch (explicit, reasoned): (a) NO `--user <nonroot>`: a fixed UID breaks bind-mount writes for images without that user and behaves unpredictably on Docker Desktop/Windows bind mounts; root-in-container is instead contained by `--cap-drop ALL` + `no-new-privileges` + read-only rootfs + no network (residual risk recorded below). (b) Single RW workspace mount instead of `:ro` + `:rw` scratch split: `forge test` writes `cache/`+`out/` relative to the project and cannot redirect all writes to a scratch dir; isolation is preserved because the mount holds ONLY harness-staged files (never repo, home, `.env`, credentials, or socket). (c) Additions over the sketch: `--pull never` (no silent image fetch, ever), `--stop-timeout 5`, tmpfs `noexec,nosuid`, per-run `--name` for reliable kill.
- Lifecycle: per-run container name; `abort()` issues `<runtime> kill <name>` + `rm -f` (idle abort is a `{aborted:false}` no-op); `run()` always `rm -f`s in `finally`; the harness owns the wall-clock timeout and calls `abort()` on expiry, so timed-out containers are killed, not orphaned (T9, T14). Stdout/stderr are captured at 1MiB/stream with explicit truncation markers; the harness truncates further to `maxLogChars` (T13). Cleanup of the host workspace stays in the harness `finally` (proven after success, failure, and timeout: T10, T13, T14).
